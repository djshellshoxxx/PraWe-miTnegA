# RevocationGap — Shared Data Model (frozen vocabulary)

**Status:** frozen contract v1.0 (RG-P03-001). This document fixes **names, identifiers, enumerations, time types, measurement vocabulary and entity ownership**. Field-level schemas for each entity are authored and owned by the element named in §8; those specs must conform to everything here and may *add* optional fields but not rename or repurpose anything defined here without a [`CONTRACT-CHANGELOG.md`](CONTRACT-CHANGELOG.md) entry. Python type notation below is illustrative of the pydantic v2 models (ADR-0007) that live in `rg_core.model.*`.

## 1. Conventions

| Topic | Rule |
|---|---|
| Naming | JSON keys and enum values are `snake_case`; Python classes `PascalCase`; model modules `rg_core.model.<area>`. |
| Immutability | All persisted/serialised models are frozen (`frozen=True`, `extra="forbid"`). "Updates" are new records referencing predecessors. |
| Versioning | Every persisted/exported document has `schema_version: "<major>.<minor>"` (e.g. `"1.0"`). Minor = additive. Major = breaking, requires a migration (RG-P11-006). |
| Integers | Nanosecond quantities are Python `int` (64-bit range suffices: 2026 epoch ≈ 1.8×10¹⁸ < 9.2×10¹⁸). In **JSON documents** they are serialised as **decimal strings** (`"1791796800123456789"`) because JavaScript numbers lose precision above 2⁵³; JSON Schema `type: string, pattern: ^-?[0-9]+$, x-rg-format: int64`. SQLite stores native INTEGER. |
| Secrets | Never in models. Models hold `SecretHandle` (§2.4) and fingerprints. |
| Free text | Bounded (`max_length` stated per field); control characters stripped at the boundary; never interpreted as markup. |
| Provenance | Every record that is not user input carries `derivation ∈ {observed, calculated, assumed, hypothesis}` (§5) and `produced_by` (component id + version). |

## 2. Identifiers and primitive types

### 2.1 Entity identifiers
`<prefix>_<ULID>` where ULID is the 26-character Crockford-base32 ULID (48-bit ms timestamp + 80-bit randomness). Generated by `IdFactory(clock, rng)` so that with a virtual clock and seeded RNG ids are deterministic. Prefixes (frozen):

| Prefix | Entity | Prefix | Entity |
|---|---|---|---|
| `exp` | Experiment | `obs` | Observation (probe attempt result) |
| `scn` | Scenario definition instance | `evd` | EvidenceItem |
| `prv` | Provider instance (configured IdP/adapter) | `fnd` | Finding |
| `tgt` | Target (service under test) | `drv` | Derived record (analysis output) |
| `idn` | Identity (test principal) | `rev` | RevocationEvent |
| `crd` | Credential instance (token/session/cookie) | `prb` | Probe definition (within an experiment) |
| `att` | Probe attempt | `tln` | Timeline entry |
| `rpt` | Report | `aud` | Audit-log record |

Stable *definition* identifiers use dotted slugs instead: scenarios `SCN-01…` in the catalog (`scenario_id: "scn.access-survives-revoked-role@1"`), assertions `assert.<name>`, adapters `idp.<name>`, actions `rev.<kind>.<variant>`, baselines `baseline.<provider>.<doc>@<version>`, requirements `FR-…`, spec elements `RG-Pnn-nnn`, tests `TST-…`, interfaces `IF-…`, schemas `SCH-…`.

### 2.2 Time types (ADR-0006; field-level spec RG-P02-001)

```python
class ClockKind(str, Enum): system = "system"; virtual = "virtual"; remote = "remote"

class TimeInstant(Model):           # a reading of a LOCAL clock (system or virtual)
    wall_ns: int                    # ns since 1970-01-01T00:00:00Z per the local wall clock at the reading
    mono_ns: int                    # ns of the local monotonic clock (arbitrary origin, non-decreasing)
    clock_id: str                   # "system" | "virtual:<run>" ; mono_ns values are comparable only within one clock_id
    read_cost_ns: int = 0           # (t_after - t_before) of the paired read; bounds the wall/mono pairing error

class ClockDomain(Model):           # a distinct time authority
    id: str                         # "local" | "target:<host>" | "idp:<prv id>" | "event-source:<name>"
    kind: Literal["local", "target", "idp", "event_source"]

class RemoteInstant(Model):         # a timestamp REPORTED by another system (never assumed accurate)
    value_ns: int                   # ns since epoch as reported (UTC)
    domain: ClockDomain
    resolution_ns: int              # 1_000_000_000 for HTTP Date / JWT NumericDate; finer for event logs
    source: Literal["http_date_header","jwt_claim","idp_event_log","idp_admin_event","caep_event","provider_api_field","operator_entry"]
    local_receipt: TimeInstant      # when we received it

class ClockOffset(Model):           # estimate of (remote_clock - local_wall_clock)
    domain: ClockDomain; offset_ns: int; uncertainty_ns: int
    method: Literal["http_date_bracket","event_pair","ntp_reference","operator_declared","none"]
    samples: int; estimated_at: TimeInstant

class TimeInterval(Model):          # between two local instants of the same clock_id
    start: TimeInstant; end: TimeInstant     # invariant: start.mono_ns <= end.mono_ns
```

Rules: (1) durations between local events use `mono_ns` differences within one `clock_id`; (2) `wall_ns` is for display and cross-system joins only; (3) a `RemoteInstant` becomes comparable with local time only through a `ClockOffset`, and the result is an *interval* `[x − u, x + u]` (never a point) — RG-P08-002; (4) a wall-clock step (NTP/VM resume) is detected when successive `(wall − mono)` offsets differ by more than `wall_step_tolerance_ns` (default 50 ms) and is recorded as a `clock_anomaly` timeline entry, lowering confidence of any measurement spanning it.

### 2.3 Measurement quantities

* `Duration = int` ns. `BoundedDuration = {lower_ns: int, upper_ns: int | None}` (`None` = unbounded above, i.e. right-censored).
* All published exposure numbers are `BoundedDuration` plus a `localization_width_ns`; a bare "delay = N s" is forbidden in models and reports (RG-P08-004, RG-P08-011).

### 2.4 Secret handles

`SecretHandle = "secret:<resolver>:<name>"` (e.g. `secret:env:RG_ALICE_PASSWORD`, `secret:keyring:rg/alice`, `secret:file:./secrets/alice.txt`). Material is resolved at the last moment through `SecretResolver` and held in `Secret` wrappers (no `repr`, no `str`, no pickling). A **fingerprint** of a credential = `sha256(material)[:12]` hex, prefixed `fp:`; fingerprints may be stored; truncation prevents recovery. Tokens in evidence are stored as `{fingerprint, type, format, decoded_header, allow-listed claims, exp/iat/nbf instants}`.

## 4. Measurement vocabulary (frozen definitions; algorithms in RG-P08-004, uncertainty in RG-P02-006/P08-002)

Let all instants below be readings of the **same local monotonic clock** (so no clock offset enters the core computation).

| Symbol | Name | Definition |
|---|---|---|
| `A_req` | revocation requested | `RevocationEvent.requested_at.mono_ns`: instant just before RG sent the state-changing request (or the operator's manual entry instant for manual events, `source=operator_entry`). |
| `A_ack` | revocation acknowledged | instant the provider's *acceptance* was received (`acknowledged_at`). For `observed` events, the instant the event was received/entered. `A_ack = None` if never acknowledged (`rejected`/`indeterminate`). |
| `E` | effective instant (unknown) | the unknown instant at which the change began to take effect at the provider; **model assumption `E ∈ [A_req, A_ack]`** (hypothesis-level; vendor-claimed effect times, e.g. Keycloak `notBefore`, are recorded as `claimed_effective_at` and used only as a cross-check). |
| `[s_i, r_i]` | probe send interval | `t_send_start`, `t_recv_end` of attempt *i* (local mono). The target evaluated the request at an unknown instant inside it. |
| `L` | last confirmed access | the attempt with the greatest `s_i` among attempts of the credential with `outcome=access_confirmed` and `s_i ≥ A_req` (sent at or after the revocation request; earlier attempts are baseline); `L = None` if none. |
| `D` | first confirmed denial (stable) | the earliest attempt `j` (after `L` if `L` exists, else after `A_req`) with `outcome=access_denied` such that the **confirmation tail** holds: no `access_confirmed` among all later attempts of the same credential and ≥ `N_confirm` consecutive denials (default 3) or denials spanning ≥ `T_confirm` (default 3 × probe interval, min 10 s) in monotone time, unless the horizon ends first (then `D` is *provisional*). |
| `T_deny` | enforcement onset (unknown) | the unknown instant after which the target rejects the credential; **entailed bound `s_L ≤ T_deny ≤ r_D`**. |
| `W` | localization width | `r_D − s_L` (how tightly sampling pins `T_deny`). |
| `X` | continued-access duration (unknown) | `T_deny − E`. **Entailed bounds** `X_lo = max(0, s_L − A_ack)`, `X_hi = r_D − A_req`. If `L` is `None` ⇒ `X_lo = 0` ("no continued access observed", still subject to controls). If `D` is `None` (horizon reached) ⇒ `X_hi = None` (right-censored) and `X_lo` as above. If `A_ack` is `None` ⇒ no exposure claim: outcome `inconclusive`. |
| flapping | non-monotonic enforcement | any `access_confirmed` after a prior `access_denied` for the same credential/target (reported separately; the final `D` rule above ignores earlier transient denials). |

These definitions are the only ones used in specs, tests and reports. Any derived timing statement must be expressible as a bound on `X` or `T_deny` plus `W`; claims beyond the bounds are `hypothesis`-derivation and labelled. Provider-time-based statements (event log timestamps, JWT `iat/exp`) join the computation only via `ClockOffset` intervals (RG-P08-002) and then widen the bounds by the offset uncertainty.

## 5. Evidence and derivation classes

| Derivation | Meaning | Examples |
|---|---|---|
| `observed` | directly captured with provenance | HTTP exchange bytes (redacted), response `Date`, provider admin API reply, CAEP event received |
| `calculated` | deterministic function of observed records, algorithm id+version recorded | exposure bounds `X_lo/X_hi`, clock offset estimate, confidence score |
| `assumed` | stated premise not verified in this run | "`E ∈ [A_req, A_ack]`", "target validates tokens locally" (from configuration) |
| `hypothesis` | plausible explanation, not established | "mechanism: resource-server cache TTL ≈ 60 s" |

Reports must label each statement with its class (RG-P08-011). Findings may combine classes but each field has exactly one.

## 9. Cross-entity invariants (testable; enforced by `rg_core` validators and store constraints)

1. Every `Observation.credential_ref` resolves to a `Credential` of the same experiment; every `Observation.exchange_ref` resolves to an `EvidenceItem`.
2. `Observation.t_send_start.mono_ns ≤ t_recv_end.mono_ns` and both share `clock_id`.
3. Timeline `seq` is gap-free and strictly increasing per experiment; `at.mono_ns` is non-decreasing along `seq` except `operator_action` entries that carry an explicit `occurred_at` (marked `out_of_order=true`).
4. `RevocationEvent.acknowledged_at ≥ requested_at` (mono) when both present; `ack_state=acknowledged` ⇒ `acknowledged_at` present.
5. An `ExposureWindow` exists only if the experiment has ≥1 valid baseline `access_confirmed` observation for the credential **and** all required controls passed; otherwise the derived outcome is `inconclusive`.
6. `Finding.outcome=vulnerable` ⇒ expectation `strength=MUST` in the finding's `profile`, `confidence ≥ medium`, and `independent_validation` present.
7. No persisted record contains a substring equal to any `Secret` material resolved during the run (canary test, RG-P11-001).
8. All records of one experiment carry the same `clock_id` family (system or virtual); virtual-time results are never mixed with system-time results in one `ExposureWindow` (ADR-0014).
