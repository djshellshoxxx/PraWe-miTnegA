# ADR-0003 — Six distributions with enforced one-way dependencies

* **Status:** Accepted · **Owner:** RG-P03-001
* **Context.** Master prompt wants reusable components (temporal engine, probe engine, OAuth/OIDC adapter lib, connector framework, correlation engine, state engine, evidence analysis, evidence serialization, report generation, scenario DSL) *without* gratuitous splitting. System prompt requires that Schemathesis not leak into unrelated modules.
* **Alternatives.** (1) One monolithic package + lint rules; (2) ≥12 micro-distributions; (3) **six distributions** along real dependency/reuse seams.
* **Decision.** `revocationgap-core` (`rg_core`: pure domain, no I/O, deps: pydantic only), `revocationgap-idp` (`rg_idp`: Authlib/requests/joserfc), `revocationgap-probe` (`rg_probe`: requests, websockets), `revocationgap-stbridge` (`rg_stbridge`: schemathesis — only importer), `revocationgap-lab` (`rg_lab`: simulation/test doubles; Starlette/uvicorn), `revocationgap` (application: engine, store, config, report rendering, CLI, GUI, API, plugin loading). Seams justified by *dependency weight and reuse*: core is embeddable in other tools (no network libs); idp is reusable for any OAuth tooling; probe reusable without ST; stbridge isolates a fast-moving heavy dependency cone (pytest, hypothesis, werkzeug…); lab is test-only weight. Report renderers, store and engine stay in the app because their reuse value does not offset packaging cost (revisit in RG-P14-001).
* **Consequences.** import-linter contracts (RG-P12-006); ports (`rg_core.ports.*`) defined in core and implemented outward (hexagonal). Monorepo with `uv` workspace; versions released in lock-step.
* **Verification.** CI import-boundary job; each distribution installs and imports in a clean venv without the others except declared deps (RG-P12-005).
